## 一、核心命题

**AI 无法伪造的，是你真正的感受。**

当一切都可以被伪造，真实感受就成了最稀缺的资源。AI 让执行成本趋近于零，壁垒从「做出来」转移到「知道做什么」。而「知道做什么」的唯一可靠来源，是人们真实的需求和感受——不是点击数据，不是行为数据，而是被五层安全架构保护的、无法被伪造的感受数据。

Standby 做两件事：

### 让人重新敢于表达真实感受

现有平台贩卖注意力，数据告诉供给侧的是「用户被什么刺激吸引」，而不是「用户真正需要什么」。Standby 不贩卖注意力——它是一个安静的空间，让真实的感受自然浮现。用户因心物而触动，因共鸣而连接，因安心而表达。

### 让真实感受成为可理解的信号

用户的真实表达在端到端加密状态下聚合为群体共识，为供给侧提供「用户真正需要什么」的答案。不是行为数据，不是点击数据，而是感受数据——这个时代最稀缺、最真实、最不可伪造的数据。

**这两件事互为飞轮：** 用户越真实，平台价值越高；平台价值越高，供给侧越愿意付费；供给侧越精准，用户获得的供给越好。没有一方需要牺牲另一方来获益。

## 二、时代观察

### 2.1 技术悖论

```
技术能力 ↑  →  AI 可以生成一切  →  真假难辨  →  信任 ↓
效率工具 ↑  →  流量至上逻辑    →  对立/虚伪 ↑  →  真实表达 ↓
```

结果：人们有能力表达，但不敢表达；有渠道交流，但不愿交流。

### 2.2 AI 时代的两个选择

- 大多数产品选择用 AI 来**生成更多内容**（AI 写作、AI 绘画、AI 视频）→ 内容通胀
- Standby 选择用 AI 来**理解已有内容** → 发现人与人之间隐藏的共鸣

**AI 不应该是人与人之间的隔阂，而应该是桥梁。**

### 2.3 AI 的边界

AI 可以写一首关于孤独的诗，但它不会真的孤独。
AI 可以生成一张夕阳的照片，但它不会真的被夕阳触动。
AI 可以模拟同理心，但它不会真的理解你的痛。

**AI 时代最稀缺的资源是：真实的人类感受。Standby 是感受的空间，不是内容的平台。**

### 2.4 多巴胺 vs 内啡肽

现有平台的底层驱动力是**多巴胺**——让你「想要」更多，但永远不满足。

Standby 的底层驱动力是**内啡肽**——让你获得真实的满足感：
- 成长的满足（我理解了自己）
- 共鸣的满足（我被理解了）
- 发现的满足（我看到了新视角）
- 创造的满足（我留下了真实的东西）
- 被看见的满足（有人真的在乎我的感受）

**五种满足的功能映射**：

| 满足类型 | 产品功能 | 体验描述 |
|---------|---------|---------|
| **成长的满足** | 感受链 + 痕迹回顾 | 通过理解他人的感受来理解自己，回顾自己的表达轨迹看到成长 |
| **共鸣的满足** | 感受碰撞 + 知己发现 | 看到他人如何被同一事物触动 + "有个人总是跟你有同样的感受" |
| **发现的满足** | 心物流 + 跨话题共鸣 | 看到新视角、新事物，被差异启发 |
| **创造的满足** | 心物贡献 + 表达即价值 | 写下真实的东西，成为他人看到的"真实的别人" |
| **被看见的满足** | 知己关系 + 匿名知己 | 有人真的在乎你的感受，即使不知道你是谁 |

## 三、产品本质

### 3.1 Standby 是什么？

不是社交平台（不追求关系数量）
不是内容平台（不追求内容消费）
不是通讯工具（不追求即时通讯）

**是：让人重新敢于表达真实自我的安全空间。一个通过真实表达建立真实连接的匿名平台，同时为供给侧提供真实需求数据。**

### 3.2 一句话定位

**别的产品是「人→内容→人」，Standby 是「人→事物→感受→人」。中间多了一个「事物」心物，一切都不一样了。**

### 3.3 核心价值

| 对象 | 价值 |
|------|------|
| **对用户** | 安心感 + 真实连接 + 个人成长 |
| **对供给侧** | 真实需求数据 + 群体共识 |
| **对社会** | 减少虚假表达 + 促进真实理解 |

### 3.4 与主流平台的本质区别

| 平台 | 核心问题 | 优化目标 | 驱动力 | 社交模型 |
|------|---------|---------|--------|---------|
| 微信 | 你认识谁 | 关系维护 | 社交压力 | 好友 + 朋友圈 |
| 抖音 | 你看什么内容 | 参与度 | 多巴胺 | 内容 + 算法 |
| 微博 | 你想让别人知道什么 | 传播力 | 表演欲 | 广播 + 评论区 |
| 小红书 | 你想成为什么样的人 | 生活方式 | 焦虑 | 种草 + 分享 |
| **Standby** | **你感受到了什么** | **共鸣** | **内啡肽** | **心物 + 感受链** |

## 四、核心概念

### 4.1 心物（Seedstone）

**心物是一切交互的起点。它必须是有形的、可被体验的事物，由此生发出来的才是真挚的感情。**

```
                    真实的情感
                       ↑
               用户的反应/感受
                       ↑
    用户 A ──→  [ 锚 点 ]  ←── 用户 B
                    ↑
              现实中的某个事物
```

**没有心物，就没有表达。** 这不是限制，是过滤器——它天然地过滤掉了「为了发而发」的内容。

心物是客观内容，不是引导：
- 心物是「事物」，不是「问题」
- 心物是「触发物」，不是「引导语」
- 心物是「世界给你的」，不是「系统问你的」

心物有三种来源：**平台初始心物**（冷启动）、**用户贡献心物**（有机循环）、**AI 发现心物**（辅助丰富）。当用户自产的心物在各项表现指标上与平台初始心物没有显著差异时——产品成功了。

### 4.2 感受链（Feeling Chain）

**感受链是 Standby 的核心机制，替代传统的「内容+评论」模式。**

传统社交模型：心物 + 评论
- 我说了什么 → 你来评论 → 我回复你 → 讨论
- 本质是「广播 + 回应」

Standby 模型：心物 + 感受链
- 事物触发我 → 我表达（形成感受链条目，同时作为独立心物）→ 我的感受触发你 → 你表达 → ...
- 本质是「链式反应」，但每层都是对原心物的独立反应

**每条感受都是对心物的独立反应，不是「回复」别人。每条感受链条目同时作为独立心物存在。**

```
心物: [夕阳照片]
  │
  ├─→ A: 「让我想起外婆家门口的夕阳」  ← 独立心物 A
  ├─→ B: 「美得让人安静」              ← 独立心物 B
  └─→ C: 「这种光线下拍过一张全家福」    ← 独立心物 C

当用户点击感受链 A 进入时：
心物 A: 「让我想起外婆家门口的夕阳」
  │
  ├─→ A1: 「我外婆也喜欢看夕阳，但她已经不在了」
  └─→ A2: 「珍惜还在的人」
```

**感受链是单层结构，每条感受链条目同时作为独立心物。每条感受都是对原心物的独立反应，不是对其他感受的回复。**

### 4.3 共鸣（Resonance）

两个人对同一心物产生相似的情感反应。不是点赞，不是评论，而是「我也有过这种感觉」。

**共鸣的真正目的**：不是为了确认你的感受是对的，而是为了帮你理解你的感受可以被怎样应对。

- 共鸣：「有人跟我有同样的感觉」→ 不孤单
- 发现差异：「但 ta 的应对方式跟我不一样」→ 新视角
- 被差异启发：「我也可以试试 ta 的方式」→ 成长

**共鸣是入口，不是终点。通过理解他人来理解自己。**

### 4.4 知己（Confidant）

通过持续共鸣自然沉淀出的关系。不是加好友，不是互关，而是「我们总是不约而同地被同样的东西打动」。

**知己关系的本质是「感受的连接」，不是「身份的连接」。**

- 你不知道 ta 是谁，但你知道 ta 总是跟你有同样的感受
- 你不需要知道 ta 的真名，因为知己关系的价值在于感受的连接
- 你通过感受认识 ta，不是通过名字、长相、职业

系统检测到两个人在多个心物上反复共鸣时，会自动提示「有个人总是跟你有同样的感受」。双方都选择「想认识这个人」后，可以互相看到设定昵称和头像——但匿名性永不打破。

**关系深度是光谱，不是阶段。** 用户永远看不到数字，升级和降级是自然发生的，没有断开连接的操作。关系分存在个性化衰减，但 Standby 不是热点式平台——心物是永恒的，两个人在不同时间对同一心物产生的共鸣是真实的跨时空共鸣，不应被时间差惩罚。

### 4.5 匿名身份

所有用户在系统中都是匿名的。没有头像照片、没有真名、没有个人主页链接。只有随机生成的昵称和 emoji。不可被搜索，不可被追踪，不可被骚扰。

**匿名不等于真实，但匿名创造了真实的条件。**
- 匿名消除了表演动机（没有观众）
- 匿名消除了社会后果（没有评判）
- 匿名创造了安全空间（可以脆弱）

**强实名注册 + 全匿名展示**：注册时绑定硬件身份（一人一号），但在平台上完全匿名。这是守住底线（实名制要求）与消除表演压力之间的平衡。

### 4.6 五层安全架构

安全不是功能，是地基。攻击应在架构层面就难以组织，而非依赖运营手段事后补救。

```
第一层：硬件身份验证
    │  设备级硬件 ID 绑定，一人一号
    │  硬件 ID 经不可逆变换后作为身份凭证
    │  结构性地遏制水军和批量注册
    ↓
第二层：端到端通信
    │  完全切断通过互联网端口访问中心服务器的可能
    │  外部爬虫、API 滥用、中间人攻击在架构上不可行
    ↓
第三层：盲服务器处理
    │  用户原始表达不上服务器，端侧完成初步分析后上传抽象特征
    │  服务端基于抽象特征做聚合分析（模式检测、异常检测）
    │  即使服务器被攻破，泄露的只有抽象特征，无法还原原始内容
    ↓
第四层：完全匿名
    │  用户之间完全匿名
    │  表达内容不可追溯到任何个体
    │  知己关系是感受连接，不是身份连接
    ↓
第五层：群体行为监测
    │  真实群体表达应呈现渐进、平稳、无突变的分布
    │  突变型动向（疑似刷量、舆论操控）自动过滤不展示
    │  保护群体共识的真实性
```

五层安全体系的哲学是：**让攻击的成本高于收益，让操纵在架构上不可行。** 不是靠审核团队事后补救，而是从硬件层到数据层的结构性防护。

## 五、设计原则

### 5.1 设计原则总览

| 维度 | Standby 的选择 | 对标现状 |
|------|--------------|---------|
| **内容逻辑** | 真实 > 流量 | 流量 > 真实 |
| **AI 角色** | 守护者 + 织网者 | 助推者（放大内容、优化传播） |
| **交互形态** | 无感的、融入生活的 | 刻意的、打开 App 才存在的 |
| **设备关系** | 系统级输入，不分设备 | App 级隔离 |
| **关系建立** | 先共享体验，再发现人 | 先关注人，再看内容 |
| **反操纵** | 零检索，杜绝从众 | 搜索 + 热搜 + 推荐算法 |

**好的人与人之间的交流是无感的、真诚的、积极的。**

### 5.2 七条哲学

1. **心物驱动，非内容驱动** — 人→事物→感受→人，不是人→内容→流量→人
2. **感受链，非评论区** — 每条感受是独立反应，形成单层链式结构，每条感受链条目同时作为独立心物
3. **匿名架构，安全优先** — 攻击在架构层面就难以组织
4. **共鸣过滤，非算法推荐** — 不是「你可能喜欢」，而是「你们确实有共鸣」
5. **深度优先，非正负优先** — 深度表达优先于表面表达
6. **沉默表达，非公开表演** — 表达是匿名的，但可见的
7. **沉淀关系，非积累人脉** — 知己是自然涌现的，不是主动添加的

## 六、用户画像

### 6.1 目标用户

**大城市原子化个体**：
- 一人在大城市工作生活，家人朋友不在身边
- 渴望真挚且真实的交流、沟通和共鸣
- 对现有社交平台失望（表演压力、流量逻辑、虚假内容）
- 有表达欲望但缺乏安全的表达空间
- 想变得更好——但不想被算法「喂养」

### 6.2 用户核心需求

| 需求 | 说明 |
|------|------|
| 被理解 | 而非被看见 |
| 找到共鸣 | 而非获取关注 |
| 真实连接 | 而非社交表演 |
| 个人成长 | 通过理解他人来理解自己 |

### 6.3 用户为什么来

**因「想变好」而来**——这不是口号，是底层驱动力。用户在其他平台获得的是刺激（多巴胺），在 Standby 获得的是满足（内啡肽）。

来到之后：看到「真实的别人」→ 产生共鸣 → 感到安心（五层安全架构保证）→ 开始真实表达 → 成为其他用户看到的「真实的别人」。循环开始。

## 七、商业模式与飞轮

### 7.1 核心立场

**Standby 是完全的 To C 产品，不考虑对公或政府市场。** 所有产品设计、技术选型、商业模式均围绕个人用户展开，不为 B 端/G 端需求妥协用户体验或架构原则。

Standby 不采用以下商业模式：
- **不卖用户数据**：用户的一切表达、反应、共鸣关系不对外提供
- **不做广告**：不以流量变现，不存在广告推荐算法
- **不搞会员分级**：不通过付费解锁功能来区分用户
- **不做企业版定制**：不为 B 端客户改变产品对用户的设计原则
- **不考虑信创/政务市场**：不为适配国产化替代或政府项目改变技术架构

### 7.2 三条变现路径

**路径一：真实需求数据**

这是 Standby 最核心的商业模式，也是社会价值的直接体现。

- 用户因「想变好」而来 → 有动机提供真实表达
- 真实表达在端到端加密状态下聚合为群体共识 → 个体隐私得到结构性保护
- 群体共识（真实需求）成为可变现的产品 → 供给侧为此付费
- 供给侧根据真实需求优化产品和服务 → 用户获得更好的供给

这条路径的关键假设：**供给侧愿意为「用户真正需要什么」的答案付费**——不同于「用户被什么吸引」的行为数据，这是内啡肽驱动的、关于满足而非欲望的数据。

**路径二：跨设备生态合作**

- SDK/中间件：将核心能力封装为 SDK，设备厂商集成到自有系统中
- 深度合作/联合开发：与特定生态厂商绑定
- 场景接力：在场景切换时不让体验断裂（如从手机到手表到耳机）
- 融合感知：多设备并行融合产生状态理解
- 目标生态：小米全生态多终端统一系统（澎湃 OS）

**路径三：基于用户洞察的咨询服务**

- 趋势洞察报告：基于匿名聚合数据的趋势分析
- 决策咨询：为政策制定者、学术机构提供基于真实公众情感的数据支撑
- 社会研究：理解大规模人群的真实情感状态

### 7.3 飞轮模型

```
用户因「想变好」而来
    ↓
看到「真实的别人」→ 产生共鸣 → 感到安心（五层安全架构保证）
    ↓
开始真实表达（心物 + 感受链）
    ↓
真实表达成为其他用户看到的「真实的别人」
    ↓
共鸣自然沉淀为知己关系
    ↓
真实数据在加密状态下聚合为群体共识
    ↓
供给侧付费 → 供给侧优化产品 → 用户获得更好的供给
    ↓
飞轮加速：更好的供给 → 更好的体验 → 更多真实表达 → 更好的数据 → ...
```

**飞轮的起点是安全，飞轮的燃料是真实，飞轮的回报是成长。**

## 八、成功标准

### 8.1 核心原则

留存率、注册量、使用时长是**结果**，不是目标。追逐这些指标会导致讨好用户的设计，背离「真实表达」的产品哲学。

Standby 不做增长黑客。增长来自飞轮的自然转动，来自用户自发的「我在这里找到了真实」。

### 8.2 最终检验标准

**当用户自产的心物和平台初始心物在各项表现指标上没有显著差异时——产品成功了。**

用户不再只是消费者，而是和平台一起创造高质量的心物。心物来源的三种渠道（平台、用户、AI）界限模糊，融为一体。

### 8.3 核心假设验证

| 假设 | 验证方式 |
|------|---------|
| 用户在这个环境里会真实表达 | MVP 用户测试 |
| 供给侧会为匿名聚合的真实需求数据付费 | 案例验证 |
| 知己关系可以通过共鸣自然涌现 | 关系数据追踪 |
| 跨设备体验能形成场景接力 | 技术原型验证 |

## 九、核心概念速查

| 概念 | 定义 | 一句话理解 |
|------|------|-----------|
| **心物（Seedstone）** | 触发感受的客观事物 | 完整、具体、真实。没有心物，就没有表达 |
| **感受链（Feeling Chain）** | 表达形成的链式反应 | 单层结构，每条感受形成独立心物，不是「回复」 |
| **共鸣（Resonance）** | 对同一心物的相似情感反应 | 不是点赞，是「我也有这种感觉」 |
| **知己（Confidant）** | 通过持续共鸣自然沉淀的关系 | 感受的连接，不是身份的连接 |
| **匿名身份** | 用户在系统中的匿名展示 | 随机昵称 + emoji，不可搜索、不可追踪 |
| **五层安全** | 从硬件到群体的结构性安全体系 | 让攻击在架构层面就难以组织 |
| **真实需求数据** | 加密聚合后的群体共识 | 不是「被什么吸引」，而是「真正需要什么」 |
| **内啡肽驱动** | 满足感的底层驱动力 | 成长、共鸣、发现、创造、被看见 |

## 十、常见问题

### Q：为什么没有评论区？

传统评论区是「广播+回应」模式，本质上是围绕发布者展开的对话，支持无限嵌套的树状结构。Standby 使用「感受链」替代——每条感受都是对心物的独立反应，不是「回复」别人。感受链是单层结构，每条感受链条目同时作为独立心物存在，可以被其他用户浏览并产生新的感受。这是一种根本性的结构改变：从「围绕发布者的对话」变成「围绕心物的共鸣网络」。

### Q：为什么不能搜索用户？

为了保护匿名性。用户不能被搜索、不能被追踪、不能被骚扰。知己关系是通过共鸣自然涌现的，不是通过搜索找到的。这也是零检索设计的一部分——杜绝从众性发言，杜绝「大V效应」。

### Q：为什么没有点赞数？

点赞数会引发表演动机。当人们看到数字，就会开始为数字而表达，而不是为感受而表达。Standby 只有「共鸣」——「我也有这种感觉」，不是「我喜欢这个」。共鸣没有计数，只有存在。

### Q：知己关系如何建立？

通过持续共鸣自然沉淀。系统检测到两个人在多个心物上反复共鸣，会自动提示「有个人总是跟你有同样的感受」。双方都选择「想认识这个人」后，可以互相看到设定昵称和头像。但即使成为知己，匿名性也不会被打破——你知道的是「感受上的 ta」，不是「身份上的 ta」。

### Q：平台怎么赚钱？用户数据会被卖吗？

绝对不卖。用户数据在端到端加密状态下完成聚合，服务器只能看到加密后的群体共识，无法还原任何个体数据。商业模式有三条路径：跨设备生态合作（SDK授权）、真实需求数据（群体共识产品）、咨询服务（趋势洞察）。每条路径都不需要暴露个体数据。

### Q：没有增长黑客、没有算法推荐，怎么增长？

靠飞轮的自然转动。用户获得真实共鸣 → 感到安心 → 真实表达 → 成为其他用户的「真实别人」→ 吸引更多人来。供给侧获得真实需求 → 优化产品 → 用户获得更好供给 → 更多人来。增长来自价值，不来自操纵。

### Q：五层安全体系会不会让产品很难用？

不会。五层安全是架构层面的设计，用户感知不到它。用户感受到的是：「在这里我说话很安心」。就像HTTPS——你不需要理解加密协议，你只需要知道浏览器地址栏是绿色的。安全应该是无感的、融入架构的，不是用户需要额外操作的。

内容治理采用端侧+服务端混合架构：端侧做初步分析（敏感词、情绪检测），服务端做聚合分析（模式检测、异常检测）。原始内容不上服务器，只上传抽象特征。这样既维护了"盲服务器"的安全承诺，又实现了必要的内容治理。
